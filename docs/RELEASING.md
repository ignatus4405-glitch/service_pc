# Выпуск версий и клиентские обновления

## Обычная CI-сборка

`Build and test` собирает Release-конфигурацию, запускает текущий набор модульных тестов рекомендаций, очистки, стресс-тест логики, SMART-парсинга, классификации задержек и преобразования температурных значений (фактические CPU/RAM/дисковые проверки не запускаются) и сохраняет EXE как Actions artifact на 14 дней. Успешная CI-сборка не создаёт GitHub Release.

## Стабильный релиз

1. Завершите и протестируйте изменения; добавьте заметки в `CHANGELOG.md`.
2. Создайте tag вида `vX.Y.Z` (только три числовые части, например `v1.2.0`) на коммите, который должен стать релизом.
3. Push этого тега запускает `.github/workflows/release.yml`.
4. Скрипт `scripts/set-version.ps1` устанавливает AssemblyVersion/FileVersion в `X.Y.Z.0` и InformationalVersion в `X.Y.Z` только в runner checkout.
5. Общий скрипт `scripts/build.ps1` собирает solution с .NET 4.5 reference assemblies; при ошибке он выводит строки MSBuild/C# в GitHub annotations.
6. Workflow выполняет тесты и создаёт `PcCare-vX.Y.Z-windows.zip` с `PcCare.exe`, `PcCare.Updater.exe`, README, CHANGELOG и LICENSE в корне.
7. `softprops/action-gh-release` публикует ZIP и автоматически сгенерированные release notes.

Не публикуйте beta/pre-release теги: текущий клиент получает `/releases/latest` и понимает стабильный `vX.Y.Z`. При переименовании ZIP/ассета синхронно измените `FindWindowsPackage` в `UpdateService.cs`, release workflow и тест/документацию.

## Как клиент обновляется

- При запуске приложение делает GET к `https://api.github.com/repos/ignatus4405-glitch/service_pc/releases/latest`; snapshot диагностики не отправляется.
- Если версия релиза новее, пользователь видит окно с версией/заметками. «Да» запускает загрузку по HTTPS, распаковку и `PcCare.Updater.exe`; «Нет» откладывает установку.
- Помощник ждёт завершения приложения, копирует новую версию в текущий путь и перезапускает её. Если запись в защищённую папку не разрешена, UAC запрашивается только для операции копирования; само приложение затем запускается с обычными правами пользователя.
- Если ZIP отсутствует, загрузка или запись не удались, приложение сохраняет текущую версию и предлагает открыть страницу релиза.
- Клиент проверяет только три числовые части версии. Новую стабильную версию выпускайте с возрастающим MAJOR/MINOR/PATCH.

## Ручная проверка update flow

После опубликованного релиза запустите более старый `PcCare.exe`, нажмите **Обновления → Проверить обновления**, проверьте отказ/согласие, UAC при `Program Files` и перезапуск. Не устанавливайте production-версию с непроверенным ZIP. GitHub Release не подписан код-сертификатом; HTTPS и явное согласие пользователя — текущий механизм доверия.
