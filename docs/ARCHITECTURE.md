# Архитектура PC Care

## Стек

- C# 5, WinForms и .NET Framework 4.5: выбран минимальный runtime, совместимый с Windows 7 SP1 и классическими Windows 8/8.1 при наличии runtime.
- Приложение AnyCPU; Windows Forms — основной интерфейс. Установщик не требуется: релиз — portable ZIP.
- Сборка использует официальные .NET Framework 4.5 reference assemblies NuGet-пакета `Microsoft.NETFramework.ReferenceAssemblies.net45`.

## Слои и поток данных

1. `Program` запускает `MainForm` с manifest `asInvoker` и перечнем поддерживаемых Windows.
2. При показе формы `DiagnosticService.Run()` выполняется в фоне через `Task.Run`. Сервис читает WMI `Win32_OperatingSystem`, `Win32_Processor`, `Win32_DiskDrive`, `Win32_LogicalDisk` и `root\WMI` SMART-провайдеры `MSStorageDriver_FailurePredictStatus`, `MSStorageDriver_FailurePredictThresholds` и `MSStorageDriver_FailurePredictData`. `SmartAttributeParser` сопоставляет 12-байтовые ATA-записи с порогами; типовые названия и raw-значения остаются vendor-specific.
3. Полученный `SystemSnapshot` локально преобразуется `RecommendationEngine` в детерминированный список `Recommendation`; UI отображает эти же советы на обзорной странице и странице предложений.
4. `CleanupService` независимо от диагностики удаляет старые файлы только из пользовательской папки TEMP; выполнение требует явного подтверждения.
5. `StressTestService` по явному запросу пользователя запускает ограниченные по времени CPU/RAM-проверки: фиксированный проверочный CPU workload на обнаруженных логических ядрах (до 64 потоков) и тест шаблонов в выделенных буферах, с отменой и счётчиками несовпадений. Выделение RAM не превышает четверть текущей свободной памяти, с потолком 1 ГБ (512 МБ для 32-разрядного процесса). Выполнение локальное; тест не стартует при запуске приложения и не собирает/не отправляет системные данные.
6. Пока идёт CPU/RAM-тест, `LiveSensorService` периодически опрашивает загрузку CPU и память через WMI, а температуру — через доступные `Win32_TemperatureProbe`, `MSAcpi_ThermalZoneTemperature` и, если они уже предоставлены пользователем, WMI-провайдеры LibreHardwareMonitor/OpenHardwareMonitor. PC Care не устанавливает и не запускает внешние провайдеры. WMI-значения deci-Kelvin переводятся в °C с отбрасыванием sentinel/неправдоподобных значений. CPU temperature помечается как CPU только при явной маркировке источника; общие ACPI-зоны остаются отдельными. `LiveSensorChartPanel` строит временные графики CPU, процента свободной RAM и температур; отсутствующие значения — пробелы, а не нули. ATA SMART-температура отдельно показывается как снимок последней диагностики. Данные best-effort: если драйвер не передаёт CPU-датчик, точная температура CPU остаётся неизвестной.
7. `DiskSurfaceTestService` только после явного подтверждения открывает выбранный `\\.\PhysicalDriveN` на чтение и последовательно читает блоки по 1 MiB. UI получает прогресс, счётчики ошибок чтения и блоков с задержкой 200–999 мс / от 1 с (эвристика для блока 1 MiB, не измерение отдельного сектора); отмена проверяется между блоками, но одна операция чтения может задержаться. Запись, стирание, ремонт и remap отсутствуют; полный скан может быть долгим и требовать прав администратора.
8. `WindowsMaintenance` только запускает встроенные средства Windows; он не применяет настройки сам.
9. `UpdateService` получает `/releases/latest` GitHub API, ищет asset `*-windows.zip`. После подтверждения пакет загружается в LocalAppData, распаковывается, запускается `PcCare.Updater.exe`. Помощник ждёт завершения UI-процесса, заменяет EXE и запускает его снова.

## Основа функциональности

Набор сценариев вдохновлён привычной компоновкой уже существующих утилит: CPU-Z/HWiNFO для обзора CPU/RAM, CrystalDiskInfo для понятного SMART health-флага, BleachBit для ограниченной очистки, а также собственными утилитами Windows Optimize Drives/Disk Cleanup. PC Care не является форком этих приложений: их исходники, ресурсы, брендинг и бинарные файлы не включены. Системные значения читаются штатным WMI, обслуживание передаётся штатным компонентам Windows.

## Модель рекомендаций

- SMART `PredictFailure == true` → Critical, рекомендовать резервное копирование и проверку производителем.
- Свободно ≤5% на разделе → Critical; ≤15% → Warning.
- Доступно <10% физической памяти Windows → Warning.
- CPU load ≥85% в момент снимка → Warning с оговоркой, что это кратковременное измерение.
- Нет SMART-строк → Information «состояние не получено»; отсутствие данных никогда не считается здоровьем.
- Если нет Warning/Critical, добавляется нейтральный совет: срочных проблем по доступным данным не найдено, но это не гарантия исправности.

Пороговые правила и тесты расположены в `RecommendationEngine.cs` и `src/PcCare.Tests`.

## Поддержка и ограничения

- На Windows 7 используйте SP1 и .NET Framework 4.5+. Windows 8/8.1/10/11 используют более новую совместимую in-place версию .NET Framework.
- Доступ к SMART status/threshold/data зависит от конкретного диска, драйвера, RAID/NVMe/USB bridge; названия/сырые ATA-значения vendor-specific. SMART не универсален и не заменяет резервные копии или диагностику производителя.
- CPU usage и память периодически опрашиваются только пока идёт ручной stress test. ACPI thermal zones предоставляются не на всех системах и не гарантируют температуру CPU package; SMART temperature — приблизительный снимок последней диагностики. Нет показаний — это неизвестное значение, не признак нормы.
- Чтение `PhysicalDrive` может требовать прав администратора и занимать часы; это полное только-чтение выбранного диска, не полная копия Victoria, без записи/remap и без тестирования оборудования в CI.
- Сведения о системе не отправляются. При проверке обновлений на GitHub отправляется только обычный HTTPS GET к API; системный snapshot не включается в запрос.
- GitHub update asset скачивается по HTTPS. Релиз не подписан сертификатом кода; пользователю доступна страница исходного релиза, а обновление требует подтверждения.

## Продолжение разработки

Соблюдайте правила `AGENTS.md`. Изменения источников WMI, правил рекомендаций, очистки или update ZIP требуют синхронного теста/документации/CI. Новые библиотеки должны оставаться совместимыми с .NET Framework 4.5 и Windows 7/8.
